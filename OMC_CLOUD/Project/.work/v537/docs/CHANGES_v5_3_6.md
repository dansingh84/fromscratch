## B. The restore gate, re-based (G-T5-RESTORE)

The gate compared the encoder's output under a documented lever incantation against a **v5.0** vector, byte for byte outside the version field, as the proof that "every change since v5.0 is encoder policy behind a lever". That premise ended at minor 15: the lifting rounding (`[S5-DC]`, minor 15), coefficient saturation and the block motion field (minor 16) and the boundary predictor (minor 17) are normative transform changes no encoder lever can undo. With the vectors restored the gate measures **239,662 bytes differing** against the v5.0 vector — not a stale incantation. From v5.3.6 the gate keeps both of its checks but against a **v5.3.6 golden vector** (`c536_policy_restore_rail.omc`, made by this release's encoder with the incantation): (1) the incantation still reproduces the recorded stream outside the version field — which is what catches an unlisted default change in a later build; (2) the version field equals this build's `OMC_MINOR_T5`. The v5.0 vector stays in the folder as history, labelled. A gate that skips with rc 0 when its vector is missing (the reviewer's fix) was NOT adopted: a missing gate must fail loudly.
