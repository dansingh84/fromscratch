verification, and its default. Measurement conventions: real footage masters
(ProRes 4:2:2/10 and 4444/12 camera originals plus compressed stress clips),
worst-steady-frame accounting (frames 0–1 excluded per constraints rev. 3),
JPEG XS always at full strength (`--coding-signs 2 --coding-vpred 2
--quantization 1`, yuv input — never rgb).

differs from GR-off on matte8 by ≤ 3 codes on 0.26 % of pixels (43 733 cells /

## Verified against the constraints

**E-8 (A2 fix, 2026-08-02):** the auto slice-height rule selected 16 lines for
720p (720 divides 16), contradicting BITSTREAM §7 and putting 720p50 at
~1.2 ms — an A2 violation in the default path, inherited from v4.2. Fixed
(auto → 8 for heights ≤ 720, in both the CLI and the validator); verified
sh=8 in the stream header and rt=0 on real 720p content.

- **rt=0 (C4)**: default config, grain-replace config, and legacy-stream decode all
  byte-exact (this ledger's release gates).
- **A4**: moving-content 5-generation chain converges (per-gen loss 0.21→0.03 dB,
  inter-generation distance 61.5→69.6 dB); static scope unchanged from v4.2.
- **A5**: burst corruption → 1 slice concealed, damage bounded to its 16 rows of
  one frame, decode identical to clean from the next frame.
- **A1**: exact CBR (stream ≡ 32+n·F) on every stream of a 15-clip × 2–3-rate sweep.
- **A2**: no change adds a line of buffering (deadzone and context are
  per-coefficient at existing pipeline points; tables are ROM; the block field is
  header bytes inside the slice budget). The LATENCY.md table stands: 0.611 ms
  worst case (720p50) … 0.162 ms (8K60), all < 1 ms.
- **C3**: new per-pixel operations are compares/shifts only (q2 = 3 compares;
  deadzone = 1 compare vs shifted constant; classifier = 1 read + 1 compare per
  finest-band coefficient plus one per-slice pass). Table BRAM: normative K=8
  groups × 16 contexts = 128 tables ≈ 790 KB expanded (decode-side ≈ 512 KB), 2×
  the v4.2 set — chosen over the measured K=16 variant (+0.04…0.10 dB more, 4×
  BRAM) precisely because C3 says "comfortably" is literal. K=16 tables remain a
  documented option for BRAM-rich parts (gid field already carries 4 bits).
- **C1**: new ingredients are deadzone quantization (ancient), magnitude contexts
  (pre-1990 static context modelling), Lloyd-trained static tANS tables (own
  work), inter-scale classification (own work). No rANS, no CABAC, no adaptation.
