================================ U2 ================================
Ranking key = the enumeration's flag-free bit ESTIMATE, cheapest first (line numbers: rtree4
  src/codec.c after U): the cost tables bc[m][p][b].bits[s] are band_scan estimates over ALL
  coefficients of the input band INCLUDING the affected (clip-perturbed) ones (10577); the lattice
  admission SKIPS affected coefficients when forming the chunk exponents (10661/10664), so a band
  whose non-affected coefficients happen to lie on a coarser lattice admits the coarser shift;
  per band the key adds bc[m][p][b].bits[s] (10988; m = the consistent mode, the cheaper if both,
  10982; step band fan_base 10965 + fan_d*k/nch 11006); key = tk (11034); walk = argmin key, first
  on ties (11181).  Nothing in the key tests exactness; the walk then takes the cheapest VERIFIED
  and exact candidate by actual bits (11388), which is why the full walk still locks these slices.
